# 세류 음악 자동화 2.0 사용자 설명서

## 처음 실행하기

서버 PC/클라우드에 Python 3.10~3.13, FFmpeg 및 한글 폰트를 설치합니다. 실제 검증한 OS는 Linux입니다. Android에는 Python/FFmpeg를 설치하지 않습니다. 서버의 브라우저 화면에 접속하여 파일을 올리고 결과를 내려받습니다.

```sh
# Ubuntu / Debian
sudo apt-get update
sudo apt-get install -y ffmpeg fonts-noto-cjk
python3 -m venv .venv-ui
.venv-ui/bin/python -m pip install -r requirements-ui.txt
.venv-ui/bin/python main.py --check
```

기존 CLI의 requirements.txt, config.yaml 사용법은 그대로 유지합니다. Windows에서는 `py -m venv .venv-ui`, `.venv-ui\Scripts\python.exe`를 사용하고 FFmpeg/ffprobe를 PATH에 추가합니다. macOS에서는 시스템에 FFmpeg와 Noto Sans CJK KR 폰트를 설치합니다. Windows/macOS 실행은 아직 검증하지 않았습니다.

서버 로그인 정보는 환경 변수로만 지정합니다. 비밀번호는 12자 이상을 사용하세요. 비밀번호·키를 Git 파일이나 명령행 인수에 넣지 않습니다. Bash에서 비밀번호를 화면에 표시하지 않고 받는 예시:

```sh
export SERYU_UI_USER=seryu
read -rsp '서버 비밀번호: ' SERYU_UI_PASSWORD
export SERYU_UI_PASSWORD
export SERYU_DATA_DIR=/workspace/seryu-v2-data  # 클라우드의 쓰기 가능한 저장소
.venv-ui/bin/python app.py
```

일반 PC에서는 SERYU_DATA_DIR을 생략하면 사용자 홈의 `seryu-data`를 사용합니다. 실제 음원과 결과는 저장소 밖에 두세요. 기본 바인딩은 127.0.0.1:7860, 공개 공유 링크는 생성하지 않습니다. 로그인 화면에 설정한 계정으로 접속합니다. 서버가 실행 중인 PC에서만 처리하고 브라우저에는 결과를 전달합니다.

## PC와 Android 태블릿 접속

- 같은 PC: 브라우저에서 서버의 로컬 7860 포트를 엽니다.
- 같은 Wi-Fi 태블릿: 서버를 `python app.py --lan`으로 실행한 뒤 PC의 사설 IP와 7860 포트로 접속합니다. 운영자가 방화벽을 신뢰하는 LAN에만 열어야 합니다. LAN HTTP는 암호화되지 않으므로 공유 Wi-Fi에서는 사용하지 말고 TLS 프록시를 쓰세요.
- 원격 클라우드: 기본 루프백 서버를 유지하고 SSH 터널, 또는 인증된 HTTPS 역방향 프록시/VPN을 운영자가 구성합니다. 브라우저에서 접근 가능한 HTTPS 주소는 배포 환경에 따라 다릅니다. 이 프로젝트는 터널·공개 배포·외부 서비스 설정을 자동 변경하지 않습니다.
- 모바일 Chrome 등에서 파일 선택, 표 수정, MP4 재생, 다운로드를 사용합니다. 실제 Android 기기 테스트는 아직 수행하지 않았습니다. 메모리가 부족하면 이미지 용량을 줄이고 한 출력 형식만 먼저 제작하세요.

인증은 단일 공유 계정의 개인/소규모 작업용입니다. 여러 서로 다른 사용자에게 결과를 격리하는 서비스가 아닙니다. 로그인한 동일 계정 사용자는 알려진 결과 경로에 접근할 수 있습니다. 작업 조작·취소는 브라우저 세션별로 제한합니다.

## 파일 준비

1. Suno 원본 WAV 또는 MP3: 1초~30분. WAV 권장. 이미 클리핑된 원본을 복구하는 기능은 없습니다.
2. UTF-8 TXT: 실제 부른 가사를 한 줄씩 기록합니다. 반복 후렴도 빠짐없이 반복해서 적습니다. `[간주]`, `[Chorus]`처럼 대괄호만 있는 줄은 구조 표식으로 취급하고 자막에서 제외합니다.
3. 이미지 8~40장: PNG/JPG/WEBP. 드래그로 순서를 바꾸거나 `3,1,2,4,5,6,7,8`처럼 모든 번호를 중복 없이 지정합니다.
4. MP4는 선택 사항입니다. 동영상 한 개를 이미지 순서 중간에 넣습니다. 원래 영상 소리는 제외하고 짧으면 반복합니다.
5. 세류 PNG 로고: 투명 배경 권장. 모든 프레임의 오른쪽 위에 표시됩니다.
6. 수동 UTF-8 SRT는 선택 사항입니다. AI 설치 없이 SRT만 올려 제작할 수 있습니다. TXT와 SRT를 함께 올리면 자막의 가사 줄 순서와 반복이 TXT와 같아야 합니다.

파일당 최대 200MB, 전체 1000MB, TXT/SRT 각각 128KB입니다. 서버에서 업로드 경로·확장자·미디어 내용도 검사합니다. 업로드 원본은 작업별 UUID 폴더에 복사하며 사용자 파일 이름을 서버 경로로 쓰지 않습니다. 실패한 준비 파일도 임의로 삭제하지 않으므로 디스크 사용량을 운영자가 관리해야 합니다.

## 제작과 타이밍 수정

수동 SRT가 있으면 파일 선택 → 자막 확인란 선택 → **제작 시작**으로 한 번에 렌더링할 수 있습니다. 먼저 **입력 준비 / 자막 불러오기**를 누르면 표에서 타이밍을 검토할 수 있습니다.

TXT만 있는 경우 입력 준비 후 **가사 자동 정렬**을 누르거나 **제작 시작**으로 정렬 후보를 만듭니다. 자동 결과는 곧바로 제작하지 않습니다. 음원을 듣고 줄별 시작·끝 시간을 확인한 뒤 확인란을 선택하고 제작 시작을 누릅니다. 미정렬 줄은 시간이 빈 상태로 남고, 저신뢰 줄은 표시됩니다. 시간을 임의로 균등 배분하지 않습니다. AI를 사용할 수 없으면 수동 SRT를 업로드하세요.

표에서 시간을 초 단위로 수정합니다. **선택 줄 타이밍 청취**로 해당 구간 오디오를 확인할 수 있습니다. 각 줄은 0초 이상, 끝은 음원 길이 이내이며 줄끼리 겹치지 않아야 합니다. 연주 구간은 자막 사이의 공백으로 남습니다. 가사 순서와 반복 후렴은 유지합니다. AI 신뢰 지표는 정확도 확률이 아니라 ASR 확신·문자 일치·CTC 점수의 보수적인 검토 지표입니다.

제작 후 미리보기에서 결과를 보고 타이밍을 수정한 뒤 다시 제작하면 새 revision 결과가 만들어집니다. 기존 revision을 덮어쓰지 않습니다. 재시작하면 메모리에 있던 작업 세션은 복원되지 않습니다. 파일은 보존되므로 다운로드한 SRT를 다시 업로드해 새 작업을 준비하세요.

## 영상과 마스터링 설정

- 16:9 1920×1080 또는 9:16 1080×1920, H.264 yuv420p/AAC 192kbps MP4.
- 음악과 첫 영상은 0초에 시작합니다. 제목 화면·시작 페이드·검은 화면을 추가하지 않습니다. 업로드 이미지 자체가 검은색이면 그대로 표시됩니다.
- 모든 미디어의 기본 구간은 거의 균등합니다. 동영상과 이미지를 섞고, 선택적인 크로스페이드는 영상만 겹칩니다. 전체 길이는 음원 길이에 맞추며 전환은 최소 구간의 절반보다 짧아야 합니다.
- 16:9 / 9:16 크롭 위치를 따로 지정합니다. 0은 왼쪽/위, 1은 오른쪽/아래입니다. 자동 피사체 추적은 없습니다.
- 자막 크기는 ASS의 논리 크기입니다. 아래/중앙/위 위치를 선택할 수 있습니다. 긴 가사는 줄을 짧게 나눠 검토하세요.
- 끝부분 다음 곡 안내는 기존 영상 위에 겹칩니다. 추가 무음·타이틀 영상은 없습니다. 긴 안내 문구는 직접 줄바꿈하세요.
- 마스터링은 기존 FFmpeg two-pass loudnorm입니다. 기본 -14 LUFS / -2 dBTP / LRA 11, 48kHz 스테레오 24bit WAV. 마스터 피크와 최종 AAC 피크를 측정하고 AAC 0 dBTP 이상이면 실패합니다.
- 원본 SHA-256, 영상/음원 길이, 음량·피크·자막 설정·가사 검토 정보를 report.json에 저장합니다.
- 볼륨 정규화로 다이내믹이 바뀔 수 있습니다. **원본과 비교한 청감 검증은 필수**이며 전문 마스터링 품질을 보장하지 않습니다.

결과 폴더: `SERYU_DATA_DIR/results/<job UUID>/<revision UUID>/`.
`youtube.mp4`, `shorts.mp4`(선택한 형식만), `mastered.wav`, `lyrics.srt`, `report.json`을 내려받을 수 있습니다. 입력·설정은 `private/`에 보관하고 HTTP 파일 제공을 차단합니다. 취소 시 FFmpeg/AI 자식 프로세스를 종료하고 이전 결과를 보존합니다. 이미 최종 파일이 생성된 직후의 취소·오류는 `INCOMPLETE.txt`로 표시하며 완성 결과로 표시하지 않습니다.

## 선택적인 AI 설치와 모델

현재 클라우드에서는 GPU 도구가 없고 Hugging Face 접속이 403으로 차단됩니다. **실제 한국어 노래 정렬 정확도는 검증되지 않았습니다.** 자동 정렬은 실험 기능이며 수동 SRT 경로는 독립적으로 검증했습니다.

최신 Gradio 6.30.0과 WhisperX 3.8.6의 huggingface-hub 요구 범위가 서로 겹치지 않으므로 **AI는 별도 가상환경**에 설치합니다. WhisperX는 PyTorch 2.8.x 등 큰 의존성이 필요합니다. CPU/CUDA에 맞는 PyTorch 공식 설치 지침으로 먼저 구성하세요. 이 환경에서 AI 전체 설치/모델 실행은 완료하지 않았습니다.

```sh
python3 -m venv .venv-ai
.venv-ai/bin/python -m pip install -r requirements-ai.txt
export SERYU_AI_PYTHON="$PWD/.venv-ai/bin/python"
export SERYU_AI_DEVICE=cpu  # 검증된 CUDA 환경에서만 cuda로 변경
export SERYU_MODEL_CACHE=/path/to/model-cache
export SERYU_ASR_MODEL=small
export SERYU_ALIGN_MODEL=/path/to/local-korean-ctc-model
```

기본은 로컬 캐시만 사용합니다. 운영자가 모델 다운로드를 허용하려면 `SERYU_ALLOW_MODEL_DOWNLOAD=1`을 지정하고 SERYU_ALIGN_MODEL을 Hugging Face 모델 ID로 설정합니다. 기본 한국어 CTC 모델은 WhisperX가 한국어용으로 지정하는 `kresnik/wav2vec2-large-xlsr-korean`입니다. 네트워크 제한 환경에서는 huggingface.co 및 모델 다운로드가 리다이렉트하는 실제 hf.co/Xet CDN 호스트가 허용되어야 합니다. API 키나 diarization 인증은 요구하지 않습니다. 모델 라이선스와 배포 권한을 확인하세요.

알고리즘은 faster-whisper 한국어 단어 인식 → 제공 가사의 순서/반복을 유지하는 단조 문자 대조 → 인식된 구간 안에서 제공 가사의 WhisperX CTC 정렬입니다. 원문을 ASR 가사로 바꾸지 않습니다. 정렬 실패·누락 문자는 미정렬/저신뢰로 표시하고 보간하거나 가짜 시간을 넣지 않습니다. 반주·합창·긴 모음은 일반 음성 모델에 어려우므로 반드시 실제 곡에서 검토해야 합니다. 품질 검증 방법은 [AI 검증 안내](ALIGNMENT_VALIDATION.md)를 참고하세요.

## 문제 해결

- FFmpeg 누락: FFmpeg/ffprobe PATH와 필수 필터를 확인하고 `main.py --check` 실행.
- 한글 네모: Noto Sans CJK KR 설치. 폰트 경고가 나오면 시스템 폰트 캐시 쓰기 권한도 확인.
- 음원 무음: loudnorm 분석이 실패합니다. 실제 음원이 맞는지 확인.
- AI 설치/모델 오류: 수동 SRT를 업로드합니다. 에러가 나도 균등 타이밍 자막을 생성하지 않습니다.
- 전환 오류: 전환 시간을 줄이거나 0으로 변경.
- 작업 취소: 준비된 작업의 **현재 작업 취소**를 누릅니다. 기다리는 작업을 막는 버튼은 아니며 현재 실행 프로세스만 취소합니다. 서버는 작업 큐를 최대 8개, 동시 무거운 작업을 1개로 제한합니다.
- 서버 저장 공간: 작업 원본·결과를 자동 삭제하지 않습니다. 다운로드·보관 정책은 운영자가 정하세요.
